# 课程知识库升级方案（2026-09-15）

针对两条意见：**① 只有文字没有图；② 与 AI 之间有壁垒，"问这门课"不如直接看书。**

---

## 一、GitHub 上这类"专业知识整合"是怎么做的

### 1. 知识库 / 文档问答这一派

| 项目 | Stars | 关键做法 |
|---|---:|---|
| AnythingLLM | 60k+ | 三栏工作台 + 多工作区隔离 + 模型路由 + 记忆；最接近 NotebookLM 的交互 |
| Open Notebook | 25k+ | 三栏（资料列表 / 预览 / AI 对话），引用溯源，可自托管 |
| kotaemon | 25k+ | **混合检索（全文 + 向量）+ 重排序**，多模态解析图表表格，高级引用与文档预览 |
| SurfSense | 14k+ | 两阶段 RAG（2-tier），检索精度高于普通 RAG |
| LightRAG（HKUDS） | 29k+ | **图增强索引 + 双层检索 + 增量更新**，EMNLP 2025；比微软 GraphRAG 轻、省 |
| GraphRAG（微软） | — | 实体关系抽取 → 知识图谱 → 社区摘要 → Global/Local 查询；效果好但索引贵、难增量 |

**共性**：没有一家是"检索一堆文本 → 让 AI 复述"。它们都在做三件事——检索更准（混合检索/重排序/图增强）、引用可溯源、**把资料与对话放在同一屏**。

### 2. 可视化 / 教学这一派

| 项目 | 关键做法 |
|---|---|
| MakerBOT | 问一个问题 → AI 同时给解释和**实时生成的交互式可视化组件**（React + iframe 沙箱） |
| math2visual | **1,549 个 SVG 图元库** + AI 生成 SVG，双引擎（形式化 / 直观两种图） |
| AI-Knowledge-Mapper | 一个主题 → 多智能体（研究 → 综合 → 映射）→ 可下载的概念图 SVG |
| fireworks-tech-graph | 自然语言 → 生产级 SVG/PNG 技术图，14 种 UML、7 种风格 |
| excalidraw-diagram-generator | 输出可编辑的 .excalidraw JSON |

**关键分野**：图有两条路——
- **预置图元库**（math2visual 路线）：准确、可控，适合工程专业的构造图、受力图；
- **AI 实时生成**（MakerBOT / fireworks 路线）：灵活，适合流程、关系、对比类图。

**对本项目的判断**：土木/道桥的构造图与受力图**不能让 AI 临场画**——画错一个支座位置就是教错。所以主线走预置图元库，AI 只负责解释、流程和自测。

### 3. 结论：差距不在模型，在"输出形态"

同行的趋势是 **结构化知识 + 生成式 UI**：AI 的输出不是一段 markdown，而是可以直接渲染成卡片、图、可交互组件的**结构化对象**。我们原来恰好卡在最原始的一环——纯文本。

## 三、下一步（按性价比排序）

1. **图元扩容** —— 每门课 15–25 张，优先覆盖高频考点章（桥梁第 6 章、结构原理受弯构件、道路勘测平面线形、水力学明渠流、交通工程三参数）。这是"有图"从 5 张变成体系的关键。
2. **概念地图** —— `concepts.json` 里已有 `relations` 字段，可直接生成 SVG 概念图（章内概念关系网），**不需要引入图数据库或 GraphRAG 那套重索引**。
3. **生成式 UI** —— 让教练输出结构化 JSON（概念卡 / 公式卡 / 图示卡 / 步骤卡 / 对比表 / 自测题卡），前端按类型渲染；AI 回答中引用知识库条目 ID 时直接渲染成可点击卡片 —— 这一条做完，"壁垒"才算真正拆掉。
4. **自测题闭环** —— AI 出题 → 作答 → 判分 → 进错题本（对接已有的 `js/srs.js`）。
5. **教材原文接入** —— `kbcore.py` 已经支持 `chunks/<subject>.jsonl`，把教材页级文本灌进去后，引用能精确到页码，不再全是"页码未解析"。
6. **流式输出 + 停止按钮** —— 解决长回答的等待感。

# 第三轮：让 AI 更专业（同日晚）

用户诉求原话：*"训练一个道桥方向的强化学习，让它疯狂学论文和书籍，至少达到 985 教授水平"*。

## 先纠正一个技术前提

**强化学习（RL）不负责"装知识"。** RL 是让智能体在奖励信号下学策略（AlphaGo、DPO/GRPO 对齐人类偏好），它优化的是**行为**，不是**知识量**。想让模型在道桥专业上变强，正确路径是三件事：权威语料 → 检索/引用约束 → 领域微调。

而且"达到 985 教授水平"这个目标本身不可承诺，原因有三：
1. 教授的价值在**判断力与工程经验**，不在知识量；
2. 即使是浙大 BridgeGPT（见下）这种领域微调模型，在 BridgeBench 上也只比同尺寸 Qwen2.5-7B 高 **7.3%**（挑战子集 12.09%）——这是显著提升，不是"教授级"；
3. 现有权威评测（AEI 2025）的结论是：**数据稀缺时 prompt+RAG 更优；有足量监督数据时微调才发挥小模型潜力**。我们目前处在第一阶段。

## GitHub / 学术界的现成方法（第二轮调研）

| 项目 / 论文 | 方法 | 对我们的用处 |
|---|---|---|
| **BridgeGPT**（浙大 EmNets，ACL 2025，[guocheng519/BridgeGPT](https://github.com/guocheng519/BridgeGPT)） | 首个桥梁工程专属 LLM，Qwen2.5-7B 微调；配套 **SDBench** 从教材/调查生成**均匀分布**的指令集与评测集 BridgeBench | 方法与模型都可借鉴；ModelScope 有 BridgeGPT-7B-Instruct-v0.1 可下载 |
| **SDBench 方法论** | 用领域调查/教材自动生成训练与评测数据，降低专家人力依赖 | 我们已有结构化知识库，可直接生成 QA 对，比从 PDF 抽更干净 |
| **AEI 2025**（Toward construction-specialized SLMs） | 对比 prompt / RAG / 任务微调 / 预训练+微调四种策略 | 给出了路线选择依据：现在做 RAG+prompt，攒够数据再谈微调 |
| **arXiv 2603.13307** | GraphRAG vs QLoRA 对比：8B + 715 条 KG 生成 QA 的 QLoRA **胜过** 20B 的 GraphRAG 与 20B 基线 | 说明小样本高质量领域数据非常有效——我们的知识库正好是这种数据 |
| **BuildEng**（Qwen2.5-1.5B LoRA） | 训练目标不是灌知识，而是**减少自信的错误答案**、拒绝在不完整输入下给结论、inspection-first | 最有借鉴价值的一条：**"专业"的本质是知道边界** |
| Qwen2.5-3B civil blind spots | 5000–10000 条规范/计算/材料 QA（Eurocode2、ACI318、开放论文） | 数据集规模参考 |

**本机约束**：Intel Arc 集显、**无 NVIDIA CUDA**，31.5GB RAM。Unsloth/QLoRA 微调基本不可行。所以本轮落地的是**不需要 GPU 的三件事**。

## 四、暂时不做

- **不上 GraphRAG / LightRAG**：我们的知识已经是结构化的（概念/公式/题型/规范各自成条），图谱的价值主要在概念地图（第 2 条）就能拿到，不必引入实体抽取与图索引的重成本。
- **不让 AI 临场画工程构造图**：准确性风险高于收益。

## 诚实说明：教材下拉不是「按书过滤」

知识库条目只标了课程，没有标「这条来自哪本书」（`cite.book` 一律是课程名）。所以教材下拉做的是**口径声明 + 把这本书的作者/版次/ISBN/怎么读喂给 AI**，不是硬过滤。硬过滤会假装有这个能力，反而更糟。
