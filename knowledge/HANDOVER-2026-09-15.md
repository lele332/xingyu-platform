## 1. 现在是什么样

### 1.1 一句话

9 门专业课的结构化知识库（**2414 条条目**）＋ 一个常驻的「课程教练」对话面板。
课程内容和 AI 在**同一屏**，点任何一张卡片都能直接问 AI，回答里的任意一句话／任意一小节都能就地追问。

### 1.2 界面结构（`index.html` → `#view-kb`）

```
┌──────────────┬────────────────────────────┬──────────────────┐
│ 课程列表      │ 课程库内容                  │ 常驻课程教练      │
│ （9 门）      │ 章节地图/概念/公式/题型/     │ 范围：教材+章节   │
│              │ 规范/文献/参考书             │ 意图 chips        │
│              │ 每张卡有「就这个问 AI」      │ 对话线程（追加）  │
│              │                            │ 输入框 + 快捷键    │
└──────────────┴────────────────────────────┴──────────────────┘
                                              「专注」按钮可只留教练栏
```

### 1.3 一次提问的完整链路

| 步骤 | 位置 | 说明 |
|---|---|---|
| 1 | `js/course-kb.js` `doAsk()` | 读输入框 / 卡片预设问题 / 追问模板 |
| 2 | `GET /api/kb/context?q=&subject=&top=8&chapter=` | `server.py:764` → `kbcore.assemble_context()` |
| 3 | `kbcore.Index.search()` | Contextual BM25（中文 uni+bi-gram）＋ 精确短语奖励 ＋ 字段权重 ＋ 学科先验 ＋ **反馈权重** |
| 4 | `kbcore.assemble_context()` | 组装带编号的证据块 ＋ 引用列表 ＋ 使用规则 |
| 5 | `server.py:_kb_prompt()` | 把 `knowledge/prompts/coach-system.md` 作为 system prompt 注入 |
| 6 | `AI.chat(msgs)` | 带最近 3 轮历史，temperature 0.3 |
| 7 | `renderThread()` | 追加一轮到线程（**不覆盖上一轮**），渲染 Markdown/LaTeX/图 |

## 2. 数据在哪、怎么加

### 2.1 目录

```
knowledge/
├── SCHEMA.md                     字段契约（改数据前必读）
├── catalog/subjects.json         9 门课的登记（id / 名称 / 版次 / 别名）
├── prompts/coach-system.md       教练人设与 8 条铁律（**改 AI 行为改这里**）
├── subjects/<sid>/
│   ├── syllabus.json             章节地图
│   ├── concepts.json             概念卡
│   ├── formulas.json             公式卡（含可计算 expr + vars）
│   ├── exercises.json            典型题
│   ├── standards.json            规范索引
│   ├── books.json                参考书（已核实版次/ISBN）
│   └── sources.json              文献源索引（**9 门课都有**）
├── assets/<sid>/*.svg            本地配图（目前 bridge-engineering 5 张、engineering-economics 5 张）
└── feedback.json                 用户反馈权重（自动生成，勿手改）
```

### 2.2 加内容的三个动作

| 想加什么 | 怎么做 | 注意 |
|---|---|---|
| 一条概念/公式/题 | 往对应 `*.json` 的 `items` 里加对象 | `id` 必须 `<sid>-<kind>-NNN`；`confidence` 只能是 high/medium/low；没把握就写 `verify` |
| 一张图 | 1) 画 SVG 放 `assets/<sid>/`　2) 给条目加 `figure{src,caption,readPoints}` | **示意图，不冒充教材原图**；`readPoints` 要写"看哪条线、哪个量"，不能只复述文字 |
| 一本书 | 加进 `books.json`，填 `verification{status,source,checkedAt,note}` | 纠正原值时**必须在 note 写明原值与依据**，不得静默改写 |
| 一个文献源 | 加进 `sources.json` | 只登记"去哪儿查"，**不入库论文全文**（版权 + 不可核） |

### 2.3 改完必须做的两件事

1. 索引按文件签名（大小 + mtime）自动重建，**不用重启服务**；
2. 前端有 Service Worker 版本化缓存，**改了 js/css 必须把 `index.html` 里的 `?v=YYYYMMDD.N` 加 1**，否则用户看不到。

## 4. 交互约定（别改回去）

| 约定 | 原因 |
|---|---|
| 课程库与教练**同屏**，不分成两个 tab | 用户明确反馈"有割裂感"；上一版两个 tab 被否 |
| 追问只追加，**绝不覆盖上一轮** | 用户：重新生成把原来已经生成的也没了 |
| 模式前缀（预习/作业/复习）**只影响生成，不污染检索** | 早期 bug：前缀里的"作业"把 BM25 带偏 |
| 卡片上必须有「就这个问 AI」 | 用户：还要在文本框里把书名打一遍，太不方便 |
| 教材下拉做的是**口径声明**，不是按书过滤 | 知识库条目没有"来自哪本书"的标记，硬过滤会假装有能力 |
| 页码一律不编造，未解析就写"页码未解析" | 数据契约，见 SCHEMA.md |

|---|---|

## 5. 已知边界（没做完 / 做不到，别当成 bug）

| 项 | 现状 | 说明 |
|---|---|---|
| **没有本地微调模型** | 用的是 DeepSeek / 方舟通用模型 + RAG | 本机 Intel Arc 集显**无 CUDA**，QLoRA/LoRA 微调跑不了。想做领域微调（参考 BridgeGPT 思路）需要云 GPU |
| **"985 教授水平"不可承诺** | 人设已按"知道自己边界"来写 | 教授的价值在判断力；公开结果里 BridgeGPT 相对基座也只高 7.3% |
| **论文全文不入库** | `sources.json` 只索引入口 | 版权 + 无法核实页码；AI 需要前沿内容时按索引去检索 |
| **教材下拉不做硬过滤** | 见 §4 | 数据结构决定的，不是漏做 |
| **配图只覆盖 2 门课** | 桥梁 5 张、工程经济学 5 张 | 其余 7 门待补；**工程图必须预设 SVG，不建议 AI 现场生成**（构造/受力图画错是有害的） |
| **页码全部"未解析"** | 没有导入教材原文 | 需要用户授权导入 PDF 并做页码映射（`knowledge/chunks/<sid>.jsonl` 已留接口） |

## 6. 下一次接手的建议顺序

1. 补齐其余 7 门课的配图（照 `assets/engineering-economics/` 的画法：660×300、浅灰描边、图上直接写"读图/易错"）。
2. 导入教材原文到 `knowledge/chunks/<sid>.jsonl`，把"页码未解析"变成真页码——**这是提升可信度收益最大的一步**。
3. 等有 GPU 环境后，用 `sources.json` 里的期刊做语料，试 8B 级 QLoRA 微调；先做评测集再谈效果。
4. 谨慎项：任何"看起来很精确"的数字（规范限值、系数、条文号）都要能说出出处，说不出就写"请查现行规范第 X 章"。
